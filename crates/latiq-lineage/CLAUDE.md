# latiq-lineage — CLAUDE.md

OpenLineage (core spec `2-0-2`) for a pond: the events + facets, the batching JSONL writer into the pond's own `lineage/` directory, the reader `get_lineage` pages, and the optional HTTP sink. Opt-in per pond, off by default. The full design note is [`docs/lineage.md`](../../docs/lineage.md) — read it before changing anything here.

## The claim this crate must never make
**An agent CAN rewrite its own provenance today.** `write_query` executes arbitrary SQL by design, DuckDB SQL can write files, and the agent can read the directory path straight out of `get_lineage`'s own response — so forging events, overwriting real ones, or deleting the directory are all reachable right now. **[#79](https://github.com/neonexia/latiq/issues/79)** tracks the per-pond sandbox that fixes it; M1 assumes trusted agents. Nothing in this crate's docs, tool descriptions, error messages or resources may say or imply that the trail is tamper-proof. See *What lineage does not promise* in `docs/lineage.md` and do not contradict it.

## Invariants
- **A lineage failure must never fail, slow or block a query.** Nothing below `record()` returns a `Result` the query path could propagate; every failure — a poisoned mutex, an unwritable directory, an event that will not serialize, a dead backend — is a `warn!` and a dropped event. If you find yourself making `record`/`EventSink::submit` fallible or awaitable, stop. (`EventSink::drain` is the one exception: shutdown only, bounded, never on a query.)
- **Serialize an event ONCE.** The writer serializes and hands the *same* `String` to the file buffer and to the sink, so the bytes a backend receives are the bytes the pond's files hold and the bytes `get_lineage` returns. A second `serde_json::to_string` anywhere else is how the wire form and the stored form come to differ — and then "OpenLineage compliant" means nothing.
- **On overflow drop the OLDEST** — the same policy in `LineageWriter`'s buffer (10 000) and `HttpSink`'s queue (1024), for the same reason: the queue only fills when writes or the backend are failing, and the events nearest the failure are the ones an investigation wants. Dropping the newest (what a bounded channel's `try_send` does) discards exactly that window.
- **Warn once per episode, not once per event.** Overflow, write failure, queue eviction and a poisoned mutex each latch a flag and warn on the *transition*; recovery clears it. A node whose backend is down posts on every query and would otherwise drown the log it shares with the access trail.
- **Batches are atomic to a reader:** write `.tmp-<uuid>` → `fsync` → rename to `<zero-padded-millis>-….jsonl`, so a reader globbing `*.jsonl` sees nothing or a whole batch, never a torn record, and sorting names sorts by time. The directory is deliberately *not* fsynced — losing a batch on a crash is acceptable, a torn record is not.
- **Protocol-neutral, with one isolated exception** (invariant 5). No MCP/gRPC/HTTP types here except `sink::HttpSink`, behind the **`http-sink` Cargo feature** that only `latiq-pond-node` enables (outside dev-dependencies — `latiq-agent-core` enables it for tests, which resolver 2 keeps out of the binary). With the feature off `reqwest` is not even a dependency, so Cargo enforces the neutrality rather than a reviewer noticing. Everything neutral sees `EventSink`, a trait over `&str`.
- **The directory must be absolute**, or the writer disables itself: a location from a node predating `lineage_dir` arrives as `""`, and joining that with a file name scatters events across the process CWD — outside any pond, outside the `remove_dir_all` that reaps one.
- **Names are conventions, and two of them are load-bearing.** `job_name` is `{pond}.{op}.{target}` with the target's leading catalog segment dropped **only when it equals the pond name** — a pond's DuckLake alias is always its own name, so keeping it made every job stutter (`shop.write_query.shop.main.orders`) in a real Marquez; a catalog that is genuinely different survives, because merging it would merge two tables into one job. A **dataset**'s `name` keeps its full `{catalog}.{schema}.{table}` qualification (consumers key datasets on it) and its namespace is `ducklake://{pond_id}`. A job must recur across runs: never a run id, a timestamp or the SQL in it.
- **A dataset states its columns only where we know them.** `facets::schema` (the standard `SchemaDatasetFacet`) carries `(name, type)` with the engine's own type name as-is — no `description`, no normalisation, no nested fields: we have none of the three, and an invented one is the column-level version of an invented input. The emitter attaches it only when `DatasetRef::fields` is non-empty, which the engine fills for the pond's own tables and never for an external source.
- **The spec is vendored, not fetched.** `spec/` holds the OpenLineage `2-0-2` schema + our facet schemas; the tests validate emitted events against them. `jsonschema` is a dev-dependency and nothing in `src/` may reference it.

## Tests
`tests/lineage.rs` — the crate's one integration binary (writer/reader/sink behaviour + schema compliance against `spec/`). Unit tests in `src/`. The emitter and the per-pond writer registry are exercised in `latiq-agent-core`'s `tests/agent_ops.rs` (`mod lineage`); the surface e2e is `crates/latiq/tests/mcp.rs`.
