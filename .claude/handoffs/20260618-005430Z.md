## Mental-model traps from this session
- **read/write split exists for 5 reasons, NOT just attribution** (user asked). They are: (1) attribution+DuckLake snapshot, (2) the read-only safety guard (`read_query` rejects mutations), (3) transaction framing (attribution issued LAST so user SQL can't forge it), (4) result shape/inline-cap vs streamed, (5) MCP agent UX (read_only_hint vs destructive_hint tools). Keep the two gRPC RPCs + MCP tools; only the CLIENT (CLI/SDK) surface is unified to one `query`.
- **Misclassification severity is asymmetric.** Write→read CANNOT happen (writes start with INSERT/UPDATE/…). Read→write only pollutes history, AND the engine already guards it (`run_write` → `is_read_for_write` → `run_read`, no snapshot). So the fix is cosmetic-safety, not a vuln.
- **SDK is NOT an agent** — it uses Data/Query gRPC + Admin/Control gRPC, **never MCP** (invariants 1 & 8). The SDK mirrors the CLI's routing, not `latiq-client` (which is the MCP agent-sim).
- **`uv run pytest` reinstalls a CACHED wheel**, clobbering a fresh `maturin develop`. Run pytest via `.venv/bin/python -m pytest` or `uv run --no-sync pytest` (documented in `sdk/python/README.md`).
- **`sdk/python` is a STANDALONE workspace** (`[workspace]` in its Cargo.toml + `exclude = ["sdk/python"]` in root Cargo.toml) so its pyo3 `extension-module` linkage never breaks `cargo test --workspace`/nightly.
- Embedded SDK reuses **production** `serve_control_plane`/`run_pond_node` (node self-registers) — do NOT re-wire the test harness. In-process reconnect-persistence is flaky (DuckDB file handoff in one process); cross-process restart is fine.
