## Mental-model traps from this session
- **Hand-rolled `&` background processes DIE unreliably in tool-call bash.** Twice I started CP+nodes with `cmd &` and they vanished mid-smoke (the node log showed it started serving, then gone). **Use `dev.sh` (nohup'd) for any live multi-process smoke** — it backgrounds + `wait_ready` properly. nginx IS installed now (`/opt/homebrew/bin/nginx` 1.31).
- **No Flight, ever.** Node-to-node + SDK Arrow streams use **Arrow IPC over our own tonic-0.12 gRPC** (`Stream/ReadArrow`). `arrow-flight@58` → tonic 0.14 (build-bloat/skew). Same hazard killed any "just add OTLP/metrics with a hyper listener" — we serve `/metrics` via axum ourselves and use `metrics-exporter-prometheus` with `default-features=false` to drop its hyper listener. (CLAUDE.md inv 5; `docs/superpowers/specs/2026-06-12-arrow-streaming-design.md`.)
- **`now()` is TIMESTAMPTZ but `last_heartbeat`/`created_at` are TIMESTAMP.** `last_heartbeat < now() - INTERVAL` → DuckDB binder error. Cast `now()::TIMESTAMP` (see `registry.rs` reap_stale_nodes + list_nodes `date_diff(...,now()::TIMESTAMP)`).
- **The CLI routes reads→ReadQuery, writes→WriteQuery** (via neutral `latiq_engine::is_read_only`). So CLI/MCP reads flow `read_collected`→`read_arrow` (Arrow hop), writes flow `run_query`. Metrics/error recording must cover BOTH paths (it does, in `agent-core/src/ops.rs`).
- **`metrics::` calls no-op silently if no global recorder is installed** — that's why agent-core can record counters and tests (which don't `init_recorder`) just pass. `init_recorder()` is idempotent (OnceLock) for the single-process full-stack harness.
- **Metric type ≠ "current vs history".** User wanted "errors/load over time, 1-min, 1-day" → that's **Prometheus retention + `rate()/increase()` on COUNTERS**, not gauges. We expose counters (over-time) + gauges (latest); Latiq stores no history.
